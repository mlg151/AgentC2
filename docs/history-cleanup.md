# Saved conversation cleanup

AgentC2 previews and deletes verified inactive Codex, Claude, and Antigravity CLI conversations on a configured SSH host. The desktop dialog supports single and bulk deletion, shows eligibility and reviewed files, requires explicit confirmation, and reports partial or uncertain outcomes. Optional per-host/provider retention runs while AgentC2 is open, in bounded daily batches. It excludes pinned, live, stale, ambiguous, and unknown-format records. Deleting history is separate from detaching or stopping a terminal and from archiving a Git worktree.

Codex uses native `codex delete --force` for supported local thread storage. Claude removes verified session transcripts, supported sidecars, and matching index entries. Antigravity CLI **1.4.4** uses its own `/resume` picker: AgentC2 searches for the exact conversation UUID, verifies the selected row and F4 confirmation, sends the provider confirmation, then checks that its trajectory database, matching `brain/` directory, SQLite sidecars, and shared summary row are gone. AgentC2 never edits Antigravity's shared SQLite index directly. The CLI has no documented noninteractive ID deletion command, and its public repository contains documentation and examples rather than the deletion implementation.

Antigravity cleanup is version-gated. Its preview checks the installed CLI version, canonical UUID, current trajectory and summary schemas, ownership, symlinks, related conversation references, and workspace locations. Older `.pb` histories, related/grouped/active records, provider-managed internal worktree paths, and unknown layouts are excluded. Picker launch uses an isolated tmux socket and neutral temporary directory. The picker can recreate volatile SQLite WAL/SHM files while reading; those are omitted from the reviewed-byte fingerprint but checked for absence afterward. Antigravity byte counts are estimates. If a confirmation is sent but its outcome cannot be verified, the result stays **unknown** and is never replayed automatically. A fresh preview is required before retrying.

The provider's [changelog](https://github.com/google-antigravity/antigravity-cli/blob/main/CHANGELOG.md) says deletion can clean provider-managed `.system_generated/worktrees`. Back up uncommitted and untracked work before enabling retention. A CLI 1.4.4 disposable test preserved a separate registered Git worktree and its tracked and untracked files; that does not establish the behavior of every provider-managed worktree. An [upstream worktree-loss report](https://github.com/google-antigravity/antigravity-cli/issues/388) was redirected by a maintainer as outside the CLI repository's scope, so it is not evidence that this CLI version deletes ordinary Git worktrees. AgentC2 does not directly delete project files or worktrees during history cleanup.

Validation includes temporary-home Python adapter fixtures, isolated SSH/Electron cleanup checks, and the desktop regression suite. On an authenticated Antigravity CLI 1.4.4 installation, AgentC2's adapter deleted one disposable conversation and then a two-conversation batch through exact-ID `/resume` search and F4 confirmation; the target trajectory, brain, sidecars, and summary row were absent afterward. An earlier disposable conversation inside a registered Git worktree preserved that worktree and both file types. Provider-managed internal worktree deletion has not been tested. Unsupported CLI versions fail closed. These operations do not provide secure erasure or claim automatic disk compaction.
