# Reconnect and recovery

AgentC2 keeps agent processes in remote tmux. Closing the desktop, losing its SSH connection, or rebooting the client computer does not stop those processes. The workspace file on the client restores tabs, Pane A/B assignments, callsigns, pins, notes, and attention cursors. A bounded summary of up to 200 units per host also preserves their names and last known states while a host is offline. The summary excludes terminal output, event details, and transcripts; it is stored with the existing private workspace file.

An attached session uses one shared SSH PTY for its desktop and paired observers. If that SSH process reports a transport loss, the terminal layer keeps the existing viewer handles and input owner, rejects writes, and reconnects to the same tmux session after 1, 2, 4, 8, 16, then at most 30 seconds between attempts. Redraw from tmux resumes the output stream. Closing the last viewer cancels the retry. A normal tmux/process exit remains an exit and is not retried. A phone must still use the existing Take control action when another device owns input.

Inventory reconciles enabled hosts every 15 seconds and host resources every five seconds. Unreachable hosts show their cached units as stale/UNKNOWN; a successful refresh replaces that host's cache and resumes normal attention classification. A newly created session is looked up by its returned tmux identity with bounded inventory retries. Those retries read state only: they never repeat a create, stop, permission decision, or provider launch. On host connection edits, the old cache is discarded so units cannot be attributed to a different SSH target.

The helper is still sent over a short-lived, host-key-verified SSH command for inventory and actions; terminal output uses the shared SSH PTY, and tmux control mode opens on demand for history scrolling. There is no remote daemon or second SSH control master. Retained scrollback remains on the remote tmux server and follows tmux's configured history limit. A reboot of the *remote host* may end tmux sessions; AgentC2 does not claim to recover those processes. When inventory returns, missing sessions are shown as unavailable in saved tabs rather than silently relaunched.

`tests/reconnect.cjs` checks owner, handle, sequence, and retry behavior with a controlled PTY. The Linux workspace regression kills only its own local SSH attachment, checks that the remote pane PID and attention IDs stay the same, and waits for automatic reattachment. Local QA can additionally set `AGENTC2_SSH_QA_BLOCK_FILE` when using a test-only SSH wrapper: the suite blocks its disposable host during desktop restart, verifies cached stale units and pane assignments, then unblocks it and checks reattachment. No provider prompt is sent by these tests.
