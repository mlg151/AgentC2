# Rules of Engagement launch profiles

AgentC2 stores a version 1 Rules of Engagement (ROE) policy in desktop settings. A new session resolves its profile in this order: a one-launch override, the selected preset's explicit profile, the SSH host default, then the legacy preset behavior. Existing presets with `fullPermissions: true` remain **Full**; those with `false` remain **Provider defaults (unverified)**. Existing managed sessions lacking launch metadata and externally attached processes display **unknown**. A background-agent attach does not change the running process's permissions.

**Full** passes the provider's existing bypass-permissions flag. **Provider defaults** adds no permission flags; a remote user's provider configuration can allow or deny actions, so AgentC2 does not call this mode gated. **Gated** is available for standard Codex and Claude commands and Antigravity structured SDK chat. Antigravity SDK chat applies `policy.safe_defaults()` with one-shot AgentC2 approval callbacks; Full chat explicitly applies `policy.allow_all()`. Codex launches with `--sandbox read-only --ask-for-approval on-request`, requiring approval to write or escape its sandbox. Claude launches with `--permission-mode default` and session-only `permissions.ask` rules for Bash, Edit, Write, and NotebookEdit. Existing provider deny rules still apply. The provider's permission system enforces the decision. AgentC2 can answer a verified Claude `PermissionRequest` through Flash Traffic; inferred attention signals cannot grant access.

Gated mode rejects custom commands and conflicting permission arguments. Antigravity CLI 1.4.4 has no verified per-session strict permission override, so it cannot be selected as gated. Its `--mode` controls edit workflow but does not establish command permission policy. A host default of Gated therefore blocks an Antigravity Terminal launch unless that launch explicitly chooses another profile. No existing process is reconfigured. The unit pane labels the **launch** profile, since users can change provider modes within the CLI after start.

These profiles are provider controls, not an OS security boundary. Shell aliases are bypassed for gated starts, but the resolved executable, provider configuration, managed organization rules, already-granted permissions, indirect shell commands, and the remote account's filesystem access still matter. The optional worktree isolates Git files and indexes, not privileges. Launch settings stay scoped to the session and do not overwrite a remote user's global provider files.

Run `AGENTC2_HOST=<isolated-ssh-host> npm run test:launch-modes` against a Linux SSH test account with Codex, Claude, Antigravity, and a `claude3` alias available. Set `AGENTC2_PROVIDER_BIN_DIR` to a directory visible on that SSH host when the binaries are outside its default `PATH`. The suite checks real CLI process arguments, tmux launch metadata, resume flags, and hook delivery without sending a model prompt. On October 21, 2026, it passed with Codex 0.163.0, Claude 2.1.306, and Antigravity 1.4.4 in an isolated SSH fixture.

`npm run test:claude-gated` exercises the installed Claude CLI with AgentC2's generated gated flags and `permissions.ask` settings. A loopback model fixture requests one Bash command in a disposable directory. The CLI emits a real `PermissionRequest` hook: denial leaves the witness file absent, while approval creates it. The test uses an isolated Claude config directory, a dummy API key, and no real model call. It validates CLI permission enforcement and hook decision handling; it does not test authentication or the live Anthropic service. Claude Code 2.1.306 passed both decisions on October 21, 2026. A live account-backed turn can be added when an authenticated QA host is available.
