# Rules of Engagement launch profiles

AgentC2 stores a version 1 Rules of Engagement (ROE) policy in desktop settings. A new session resolves its profile in this order: a one-launch override, the selected preset's explicit profile, the SSH host default, then the legacy preset behavior. Existing presets with `fullPermissions: true` remain **Full**; those with `false` remain **Provider defaults (unverified)**. Existing managed sessions lacking launch metadata and externally attached processes display **unknown**. A background-agent attach does not change the running process's permissions.

**Full** passes the provider's existing bypass-permissions flag. **Provider defaults** adds no permission flags; a remote user's provider configuration can allow or deny actions, so AgentC2 does not call this mode gated. **Gated** is available only for standard Codex and Claude commands. Codex launches with `--sandbox read-only --ask-for-approval on-request`, requiring approval to write or escape its sandbox. Claude launches with `--permission-mode default` and session-only `permissions.ask` rules for Bash, Edit, Write, and NotebookEdit. Existing provider deny rules still apply. The CLI's own permission dialog is the enforcement point; AgentC2's attention inbox only reports evidence and does not grant access.

Gated mode rejects custom commands and conflicting permission arguments. Antigravity CLI 1.4.4 has no verified per-session strict permission override, so it cannot be selected as gated. Its `--mode` controls edit workflow but does not establish command permission policy. A host default of Gated therefore blocks an Antigravity launch unless that launch explicitly chooses another profile. No existing process is reconfigured. The unit pane labels the **launch** profile, since users can change provider modes within the CLI after start.

These profiles are provider controls, not an OS security boundary. Shell aliases are bypassed for gated starts, but the resolved executable, provider configuration, managed organization rules, already-granted permissions, indirect shell commands, and the remote account's filesystem access still matter. The optional worktree isolates Git files and indexes, not privileges. Launch settings stay scoped to the session and do not overwrite a remote user's global provider files.

Provider references: [Codex sandbox and approvals](https://learn.chatgpt.com/docs/security), [Claude permission rules and precedence](https://code.claude.com/docs/en/permissions), [Antigravity CLI permission settings](https://antigravity.google/docs/cli/settings).
